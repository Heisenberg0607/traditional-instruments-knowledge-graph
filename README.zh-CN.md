# 中国传统乐器文物知识图谱

[English](README.md) | [한국어](README.ko.md) | [简体中文](README.zh-CN.md)

本项目是知识图谱课程的团队项目。

**项目简介：**
本项目从中国传统乐器相关图书中提取数据，构建基于本体的知识图谱。首先使用 MinerU 将扫描版 PDF 转换为文本，并对部分数据进行人工标注，再结合规则抽取与 BERT 类模型的命名实体识别、关系抽取，将数据结构化。大语言模型抽取作为对比实验进行评估，最终数据用于支持统计可视化与文物检索的演示网站。

[访问演示网站](https://traditional-instruments-knowledge-g.vercel.app/)

## 网站语言支持

顶部语言菜单支持选择中文、English 和 한국어。语言选择在页面跳转和刷新后仍会保留，默认语言为中文。已翻译菜单、筛选器、详情字段、图表与提示信息、乐器分类，以及常见时代名和地区名。也支持使用 `상하이 용종`、`Shanghai Yongzhong` 等韩文、英文分类名称进行检索。

## 项目概述

**问题定义：** 中国传统乐器文物的形制、出土地点、时代和收藏信息分散在文献的各个条目中，难以按条件查找文物，也不便同时考察文物之间的关系。本项目着重将这些文献描述整理为可关联的数据。

**解决方法：** 整理《中国音乐文物大系》资料，将乐器及其部件、材质、纹饰、时代、地点和机构等建模为本体。团队结合规则抽取与基于 BERT 的实体识别、关系抽取构建图谱，并通过 Vue 和 D3 实现可供探索结果的演示系统。

**成果应用：** 用户可通过关键词以及地区、乐器类型等条件检索文物记录，查看详细属性、抽取结果和相似文物。图表支持查看乐器类型、地区、时代分布，以及基于出土地点的共现关系。

- 主要成果：包含 1,080 条记录的演示数据、本体 Schema、图数据库转储文件，以及检索与可视化网站演示。
- 个人负责内容：OCR、数据预处理、数据标注、本体构建，以及参与 BERT 建模与训练。
- 项目性质：已完成的课程团队项目。

## 个人贡献

- OCR：使用 MinerU 从图像型 PDF 图书中提取中文文本。
- 数据预处理：整理 OCR 结果中的段落与字段，按文物切分记录，为标注和模型输入准备数据。
- 数据标注：参与基于 Label Studio 的人工标注。
- 本体构建：参考 classical-music 本体框架，参与使用 Protégé 对领域概念及关系进行建模。
- BERT 建模：参与基于 BERT 类模型的命名实体识别、关系抽取建模及训练。

## 数据与预处理

数据来源为《中国音乐文物大系》的 15 个地区卷。最终数据包含以体鸣乐器为主的 1,080 条文物记录，其中 533 条包含音乐性能信息。根据报告，实物数量合计为 2,817 件。一条记录可能描述多件实物，因此区分记录数与实物数量。

原始资料为文字以图像形式保存的扫描版 PDF 图书。首先使用 MinerU 进行中文 OCR 和文档版面分析，再使用 Python 整理文本并按文物切分记录。将统一字段格式后的文本导入 Label Studio，对湖北卷、北京卷共 206 条体鸣乐器记录进行人工标注。

`src/data/artifacts.json` 包含器物名称、乐器类型、时代、机构、出土地点、文献等基本字段，以及 `标注部分` 中的原文、实体与关系。实体包含文本、标签及起止位置；关系包含主体、客体、类型与置信度。1,080 条记录的 ID 均唯一。

以下为[实际 JSON 原文件](https://github.com/Heisenberg0607/traditional-instruments-knowledge-graph/blob/main/src/data/artifacts.json)第一条记录的单行示例，仅摘录主要字段，省略实体、关系及其他字段。

```json
{"record_id": "shandong_0017", "器物名称": "青州苏埠屯8号墓编铙", "乐器类型": "铙", "数量": "3", "时代": "商代晚期", "机构": "山东省文物考古研究所", "出土地点": "青州苏埠屯8号商代墓"}
```

该记录将青州苏埠屯 8 号墓出土的 3 件商代晚期编铙作为一条记录描述，同时提供乐器类型、时代、收藏机构和出土地点。

## 构建方法与系统结构

| 阶段 | 使用方法与作用 |
| --- | --- |
| 文献数字化 | 对图像型 PDF 图书使用 MinerU 的中文 OCR 与版面分析，转换为机器可读文本 |
| 预处理与人工标注 | 使用 Python 清洗文本、按文物切分记录并统一字段格式，再在 Label Studio 中进行人工标注 |
| 本体建模 | 参考 classical-music 本体框架，使用 Protégé 连接乐器、部件、材质、纹饰与历史、出土背景 |
| 规则抽取 | 抽取器物名称、类型、时代、机构、出土地点、编号、文献等格式相对稳定的记录级字段 |
| BERT 命名实体识别 | 使用 `hfl/chinese-roberta-wwm-ext`，结合 BIOES 与 CRF，识别乐器部件、纹饰、数据属性、机构、出土地点 5 类实体 |
| BERT 关系抽取 | 使用 `[E1]`、`[E2]` 标记实体对并输入 RoBERTa，分类整器尺寸、部件尺寸、数量和形状说明等关系 |
| 规则后处理 | 执行去重、字段合并、整器与部件属性校验、编号格式保护和地点边界修正等操作 |
| LLM 对比实验 | 比较 Qwen2.5-7B 与 Qwen3-14B 的提示词、5-shot 和微调设置，最终抽取采用规则 + BERT 方法 |
| 图谱构建 | 按本体整合实体与关系，存入 Neo4j 图数据库并使用 Cypher 探索 |
| 网站探索 | 使用 Vue 3、Vue Router 构建页面，Pinia 管理数据，D3 可视化分布与关系 |

处理流程为：**扫描版 PDF → MinerU OCR → 文本预处理 → 部分记录人工标注 → 规则 + BERT 抽取 → 规则后处理 → 按本体组织图谱与 JSON → 检索与可视化**。本体为标注、抽取与图谱构建提供统一的概念和关系标准；LLM 用于抽取方法的对比实验。

网站演示读取本地 JSON。检索使用字符串匹配；相似文物推荐采用部件重合度 0.4、纹饰重合度 0.4、时代接近度 0.2 的加权和。这些权重是推荐规则的配置值。

## 评估方法与结果

### 评估标准

根据知识抽取报告第 4~6 章的实验结果，整理 Precision（精确率）、Recall（召回率）和 F1。以下性能数值均为百分比（%）。BERT 实验按 8:1:1 划分训练集、验证集与测试集。NER 严格评估要求实体边界与类型一致；RE 要求主体、客体及关系类型一致。

LLM 实验区分严格匹配与宽松匹配。宽松匹配在标签一致且符合规则时，允许由单位或部分前后缀引起的边界差异。BERT NER 的 5 类为部件、纹饰、数据属性、机构和出土地点；LLM NER 的 5 类为乐器、部件、出土地点、数据属性和机构。因此，以下数值代表各自实验设置下的结果，不应视为在相同标签体系与评估集上的直接排名比较。

### BERT 类模型结果

| 评估任务 | 设置 | Precision | Recall | F1 |
| --- | --- | ---: | ---: | ---: |
| 命名实体识别（NER） | BIOES + RoBERTa + CRF | 77.27 | 75.22 | **76.23** |
| 关系抽取（RE） | 输入标准实体的 RoBERTa 关系分类 | 72.00 | 94.74 | **81.82** |

NER F1 从 BIO + RoBERTa 基线的 71.00% 提升到采用 BIOES 后的 73.00%，加入 CRF 后达到 76.23%。最终模型比基线提高 **5.23 个百分点**。分类型来看，出土地点 F1 为 94.12%，纹饰为 85.71%，但机构仅为 50.00%，仍需改进。

### LLM 结果

| 评估任务 | 模型与设置 | Precision | Recall | F1 |
| --- | --- | ---: | ---: | ---: |
| NER | Qwen2.5-7B，简单提示词、无微调 | 24.79 | 37.04 | 29.70 |
| NER 严格匹配 | Qwen3-14B，提示词优化 + 5-shot | 47.61 | 60.72 | **53.37** |
| NER 宽松匹配 | Qwen3-14B，提示词优化 + 5-shot | 56.46 | 72.01 | **63.29** |
| NER 严格匹配 | Qwen3-14B，提示词优化 + 5-shot + 微调 | 45.67 | 57.89 | 51.06 |
| NER 宽松匹配 | Qwen3-14B，提示词优化 + 5-shot + 微调 | 55.88 | 70.83 | 62.48 |
| RE，输入标准实体 | Qwen2.5-7B，简单提示词、无微调 | 8.06 | 13.89 | 10.20 |
| RE，输入标准实体 | Qwen3-14B，提示词优化 + 5-shot | 87.62 | 84.79 | 86.18 |
| RE，输入标准实体 | Qwen3-14B，报告中的微调/部署版本 | 88.32 | 85.14 | **86.70** |

### 使用预测实体的流水线评估

上述 RE 表格以给定标准实体为条件。在实际处理中，将 NER 预测实体传递给 RE 会使错误向后续阶段传播，因此单独列出该设置的结果。

| 评估任务 | 输入或条件 | Precision | Recall | F1 |
| --- | --- | ---: | ---: | ---: |
| BERT 流水线 RE | 输入 NER 预测实体 | 未报告 | 未报告 | **约 5.56** |
| Qwen3-14B 流水线 NER | 严格匹配 | 46.47 | 60.95 | 52.73 |
| Qwen3-14B 流水线 NER | 宽松匹配 | 55.77 | 73.14 | 63.28 |
| Qwen3-14B 流水线 RE | 输入 NER 预测实体 | 28.15 | 35.02 | **31.21** |

两类模型均受到实体边界错误的影响，关系抽取性能明显下降。最终构建考虑输出稳定性、可复现性与人工修正便利性，选择 **规则抽取 + BERT 抽取 + 规则后处理**。上述流水线数值来自各自的模型实验；报告未给出最终规则结合方案准确率的单独评估值。

## 安装与运行

在已安装 Node.js 和 npm 的环境中，从仓库根目录的终端执行以下命令。

```bash
npm ci
npm run dev
```

```bash
npm run preview
```

## 局限与改进方向

- 可复现范围：目前公开资料主要包括结果数据、图谱转储文件、设计文档与探索演示。如需复现 OCR 和抽取阶段，还需整理处理代码与运行配置。
- 数据一致性：需要对齐演示记录与图谱节点的统计范围，并关联原文、标注和抽取结果的处理历程。
- 评估：报告已包含 BERT、LLM 抽取评估，但仍需统一标签体系与评估集进行比较，并单独评估最终的规则结合流水线。OCR 及检索、推荐质量的定量评估也是后续任务。
- 统计解释：地区采用启发式方法推定，数量未知时按 1 处理。应结合文献收录范围与统计规则理解结果。
