# 중국 전통 악기 유물 지식그래프

고고 문헌의 악기 유물 정보를 BERT 개체명 인식과 LLM 관계 추출로 구조화하고, 온톨로지 기반 지식그래프와 검색·시각화 데모로 연결한 수업 팀 프로젝트.

[English](README.md) | [한국어](README.ko.md) | [简体中文](README.zh-CN.md)

## 웹사이트 언어 지원

상단 언어 메뉴에서 中文, English, 한국어를 선택할 수 있습니다. 선택한 언어는 페이지 이동과 새로고침 후에도 유지되며, 기본 언어는 중국어입니다. 메뉴, 필터, 상세 정보 항목, 차트·툴팁, 악기 분류, 일반적인 시대명 및 지역명을 번역했습니다. `상하이 용종`, `Shanghai Yongzhong`처럼 한국어·영어 분류명으로도 검색할 수 있습니다.

유물 고유명, 고고학 서술, 문헌, 원본 주석 및 사전에 없는 상세 시대 설명은 중국어 원문을 유지합니다. 원본 데이터와 필터 식별자는 변경하지 않습니다. 번역은 `src/i18n/messages.tsv`에서 관리하며, 각 행은 중국어 원문·영어·한국어를 탭으로 구분합니다. `npm run test:i18n`으로 번역 누락·치환값·원문 보존·다국어 검색을 검증하고, `npm run build`로 배포용 빌드를 실행합니다.

## 프로젝트 개요

문제정의: 중국 전통 악기 유물의 형태·출토지·시대·소장 정보가 문헌의 개별 항목에 분산되어 있어, 조건에 맞는 유물을 찾거나 유물 간 관계를 함께 살펴보기 어렵다. 이 프로젝트는 문헌 속 기술을 연결 가능한 데이터로 정리하는 데 초점을 맞췄다.

해결방법: 《中国音乐文物大系》의 자료를 정리하고, 악기와 부품·재질·문양·시대·장소·기관 등을 온톨로지로 모델링했다. 팀은 BERT로 엔터티를 인식하고 LLM으로 의미 관계를 추출해 그래프를 구축했으며, Vue와 D3 기반 데모에서 결과를 탐색하도록 구현했다.

결과물 활용: 사용자는 키워드와 지역·악기 유형 등의 조건으로 유물 레코드를 검색하고, 상세 속성·추출 결과·유사 유물을 조회할 수 있다. 차트에서는 악기 유형·지역·시대 분포와 출토지 기준 공출현을 살펴볼 수 있다.

- 주요 결과물: 1,080개 레코드의 데모 데이터, 온톨로지 Schema, 그래프 DB 덤프, 검색·시각화 웹 데모.
- 개인 담당: OCR, 데이터 전처리, 데이터 라벨링, 온톨로지 구축.
- 프로젝트 성격: 완료된 수업 팀 프로젝트.

## 주요 결과 및 대표 이미지

웹 데모는 검색·필터링, 유물 상세 조회, 유사 유물 추천을 제공한다. 시각화는 악기 유형 계층, 지역 분포, 지역×유형 열지도, 시대별 유형 분포, 출토지 기준 악기 공출현을 다룬다. 별도 Cypher 자료는 개별 유물의 연결 관계와 출토지·소장 기관 간 관계 탐색 사례를 담고 있다.

## 개인 기여도

- OCR: 원자료의 문자 인식 작업을 담당했다.
- 데이터 전처리: 원자료를 정리하고 후속 작업을 위한 데이터 준비를 담당했다.
- 데이터 라벨링: 문헌 데이터의 라벨링 작업에 참여했다.
- 온톨로지 구축: 도메인 지식을 구조화하는 온톨로지 구축에 참여했다.

## 데이터 및 전처리

데이터 출처는 《中国音乐文物大系》이며, 포스터는 湖北卷·北京卷·陕西卷을 대표 자료로 소개한다. 데모 JSON에는 이외 지역의 레코드도 포함되어 있다.

문헌 정리와 라벨링을 거쳐, 유물 기본 정보와 텍스트 기반 추출 결과를 함께 탐색하는 구조로 구성했다. `src/data/artifacts.json`에는 유물명·악기 유형·시대·기관·출토지·문헌 등의 필드와 엔터티·관계 항목이 들어 있다. 엔터티는 텍스트·라벨·위치 정보를, 관계는 주체·객체·유형·신뢰도 값을 담는다.

레코드 1,080개의 ID는 모두 고유하다. 한 레코드가 여러 실물 유물을 기술할 수 있으므로 레코드 수와 실물 수는 구분한다.

## 구축 방법 및 시스템 구조

| 단계 | 사용 방법과 역할 |
| --- | --- |
| 문헌 정리·라벨링 | 비정형 기술을 정리하고 엔터티 인식을 위한 데이터 기반 마련 |
| 온톨로지 모델링 | classical-music 온톨로지 프레임워크를 참조하여 악기·부품·재질·문양과 역사·출토 맥락을 연결 |
| BERT 개체명 인식 | 악기명, 시대, 재질, 형태, 출토지, 소장지 등 문헌 속 엔터티 인식 |
| LLM 관계 추출 | 악기와 시대·지역·재질·용도·문헌 출처 사이의 의미 관계 추출 |
| 그래프 구축 | 엔터티와 관계를 통합해 Neo4j 그래프 DB로 저장하고 Cypher로 탐색 |
| 웹 탐색 | Vue 3·Vue Router로 화면 구성, Pinia로 데이터 관리, D3로 분포·관계 시각화 |

웹 데모는 로컬 JSON을 읽는 구조다. 검색에는 문자열 매칭을 사용하고, 유사 유물 추천은 부품 중복도 0.4·문양 중복도 0.4·시대 근접도 0.2의 가중 합을 사용한다. 이 가중치는 추천 규칙의 구성값이다.

## 평가 방법 및 결과

| 확인 대상 | 방법 | 결과 |
| --- | --- | --- |
| 데모 데이터 규모 | JSON의 레코드와 항목 직접 집계 | 레코드 1,080개, 엔터티 항목 23,394개, 관계 항목 8,951개 |
| 그래프 문서의 규모 | `docs/schema/classes.csv`의 기재값 | 악기 노드 1,170개 |
| 프론트엔드 빌드 | Node.js 24.22.1 / npm 11.9.0에서 설치·빌드 | `npm ci`, `npm run build` 통과 |

엔터티·관계 항목 수는 반복 언급을 포함한 파일 구성 규모다. 그래프의 악기 노드 수는 Schema 문서의 집계이며, 데모 레코드 수와 집계 대상이 다르다. 이 결과는 데이터·산출물 규모와 빌드 확인을 나타내며, 추출 정확도와 검색 품질 평가는 후속 과제다.

## 설치 및 실행

Node.js와 npm이 있는 환경에서 저장소 루트의 터미널로 실행한다.

```bash
npm ci
npm run dev
```

```bash
npm run build
npm run preview
```

개발 화면은 Vite가 출력하는 주소에서 연다. 웹 데모는 포함된 JSON으로 실행된다. 그래프 DB 자료는 [덤프 파일](data/graph/知识图谱文件.dump), 탐색 예제는 [Cypher 쿼리](docs/queries.cypher)와 [그림이 포함된 Word 원본](docs/original/cypher-queries.docx)에서 확인할 수 있다. DB 복원은 별도의 Neo4j 환경에서 진행한다.

## 한계 및 개선 방향

- 재현 범위: 현재 공개 자료는 결과 데이터·그래프 덤프·설계 문서·탐색 데모를 중심으로 구성되어 있다. OCR·추출 단계까지 재현하려면 처리 코드와 실행 설정을 함께 정리할 필요가 있다.
- 데이터 정합성: 데모 레코드와 그래프 노드의 집계 범위를 맞추고, 원문·라벨·추출 결과의 이력을 연결하는 작업이 필요하다.
- 평가: 라벨링 기준과 평가셋을 정리하고, OCR·개체명 인식·관계 추출·검색을 단계별로 평가하는 것이 후속 과제다.
- 통계 해석: 지역은 휴리스틱으로 추정하며 수량 미상은 1로 처리한다. 문헌 수록 범위와 집계 규칙을 함께 고려해야 한다.
